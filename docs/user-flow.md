# 사용자 흐름

## 목적

이 문서는 Todo App MVP에서 사용자가 앱을 사용하는 주요 흐름과 화면 상태를 정의한다.

이 문서는 이후 Figma 화면 설계와 UI 구현의 기준으로 사용한다.

## 기본 흐름

```text
앱 진입
-> 빈 상태 확인
-> 할 일 입력
-> 할 일 추가
-> 남은 할 일 확인
-> 할 일 완료 처리
-> 필요 시 완료 취소
-> 필요 없는 할 일 삭제
```

## 1. 앱 첫 진입

### 상황

사용자가 앱을 처음 연다.

### 기대 상태

- 할 일 목록이 비어 있다.
- 사용자는 할 일을 입력할 수 있는 입력창을 바로 볼 수 있다.
- 빈 상태 메시지를 통해 현재 등록된 할 일이 없음을 알 수 있다.
- 남은 할 일 개수는 0으로 표시된다.

## 2. 첫 할 일 추가

### 상황

사용자가 입력창에 할 일을 작성하고 추가 동작을 실행한다.

### 기대 상태

- 입력한 할 일이 목록에 추가된다.
- 새 할 일은 미완료 상태로 표시된다.
- 입력창은 비워진다.
- 빈 상태 메시지는 사라진다.
- 남은 할 일 개수는 1로 표시된다.

## 3. 빈 입력 제출

### 상황

사용자가 비어 있는 입력값이나 공백만 입력한 상태로 추가 동작을 실행한다.

### 기대 상태

- 새 할 일은 추가되지 않는다.
- 사용자에게 에러 메시지를 보여준다.
- 입력창은 계속 사용할 수 있다.
- 사용자가 유효한 값을 입력하면 에러 메시지는 해소된다.

## 4. 여러 할 일 추가

### 상황

사용자가 여러 개의 할 일을 차례로 추가한다.

### 기대 상태

- 추가된 할 일은 목록에서 확인할 수 있다.
- 각 할 일은 독립적으로 완료 처리하거나 삭제할 수 있다.
- 남은 할 일 개수는 미완료 항목 수와 일치한다.

## 5. 할 일 완료 처리

### 상황

사용자가 미완료 할 일을 체크한다.

### 기대 상태

- 해당 할 일은 완료 상태가 된다.
- 완료된 할 일은 목록에 그대로 남아 있다.
- 완료된 할 일은 체크박스, 낮은 강조도, 필요 시 취소선으로 구분된다.
- 남은 할 일 개수는 1 감소한다.

## 6. 완료 취소

### 상황

사용자가 완료된 할 일의 체크를 해제한다.

### 기대 상태

- 해당 할 일은 다시 미완료 상태가 된다.
- 미완료 할 일과 같은 시각적 강조도를 가진다.
- 남은 할 일 개수는 1 증가한다.

## 7. 할 일 삭제

### 상황

사용자가 특정 할 일의 삭제 동작을 실행한다.

### 기대 상태

- 해당 할 일은 목록에서 사라진다.
- 삭제된 할 일이 미완료 상태였다면 남은 할 일 개수는 1 감소한다.
- 삭제된 할 일이 완료 상태였다면 남은 할 일 개수는 변경되지 않는다.
- 삭제 후 할 일이 하나도 없다면 빈 상태 메시지를 보여준다.

## Figma에서 필요한 화면 상태

Figma에서는 최소한 다음 상태를 표현한다.

- 빈 상태
- 할 일이 있는 기본 상태
- 완료된 할 일이 포함된 상태
- 빈 입력 에러 상태
