# 사용자 흐름

## 목적

이 문서는 Todo App MVP와 승인된 확장 기능에서 사용자가 앱을 사용하는 주요 흐름과 화면 상태를 정의한다.

이 문서는 이후 Figma 화면 설계와 UI 구현의 기준으로 사용한다.

## 기본 흐름

```text
앱 진입
-> 로그인 여부 확인
-> 미로그인 시 로그인 또는 회원가입
-> 로그인 성공
-> 빈 상태 확인
-> 할 일 입력
-> 할 일 추가
-> 남은 할 일 확인
-> 필요 시 할 일 메모 추가
-> 할 일 완료 처리
-> 필요 시 완료 취소
-> 필요 없는 할 일 삭제
-> 필요 시 로그아웃
```

## 인증 흐름

```text
회원가입
-> 로그인 ID, 닉네임, 이메일, 비밀번호 입력
-> 가입 완료
-> 로그인
-> Todo 앱 진입
```

```text
아이디 찾기
-> 이메일 입력
-> 인증 코드 메일 발송
-> 인증 코드 입력
-> 로그인 ID 확인
```

```text
비밀번호 재설정
-> 이메일 입력
-> 인증 코드 메일 발송
-> 인증 코드 입력
-> 새 비밀번호 입력
-> 로그인
```

## 1. 앱 첫 진입

### 상황

사용자가 앱을 처음 연다.

### 기대 상태

- 로그인하지 않은 사용자는 로그인 화면을 먼저 본다.
- 로그인한 사용자는 Todo 목록 화면을 본다.
- 할 일 목록이 비어 있다.
- 사용자는 할 일을 입력할 수 있는 입력창을 바로 볼 수 있다.
- 빈 상태 메시지를 통해 현재 등록된 할 일이 없음을 알 수 있다.
- 남은 할 일 개수는 0으로 표시된다.

## 2. 첫 할 일 추가

### 상황

사용자가 입력창에 할 일을 작성하고 추가 동작을 실행한다.

### 기대 상태

- 입력한 할 일이 목록에 추가된다.
- 새 할 일은 미완료 상태로 표시된다.
- 입력창은 비워진다.
- 빈 상태 메시지는 사라진다.
- 남은 할 일 개수는 1로 표시된다.

## 3. 빈 입력 제출

### 상황

사용자가 비어 있는 입력값이나 공백만 입력한 상태로 추가 동작을 실행한다.

### 기대 상태

- 새 할 일은 추가되지 않는다.
- 사용자에게 에러 메시지를 보여준다.
- 입력창은 계속 사용할 수 있다.
- 사용자가 유효한 값을 입력하면 에러 메시지는 해소된다.

## 4. 여러 할 일 추가

### 상황

사용자가 여러 개의 할 일을 차례로 추가한다.

### 기대 상태

- 추가된 할 일은 목록에서 확인할 수 있다.
- 각 할 일은 독립적으로 완료 처리하거나 삭제할 수 있다.
- 남은 할 일 개수는 미완료 항목 수와 일치한다.

## 5. 할 일 완료 처리

### 상황

사용자가 미완료 할 일을 체크한다.

### 기대 상태

- 해당 할 일은 완료 상태가 된다.
- 완료된 할 일은 목록에 그대로 남아 있다.
- 완료된 할 일은 체크박스, 낮은 강조도, 필요 시 취소선으로 구분된다.
- 남은 할 일 개수는 1 감소한다.

## 6. 완료 취소

### 상황

사용자가 완료된 할 일의 체크를 해제한다.

### 기대 상태

- 해당 할 일은 다시 미완료 상태가 된다.
- 미완료 할 일과 같은 시각적 강조도를 가진다.
- 남은 할 일 개수는 1 증가한다.

## 7. 할 일 삭제

### 상황

사용자가 특정 할 일의 삭제 동작을 실행한다.

### 기대 상태

- 해당 할 일은 목록에서 사라진다.
- 삭제된 할 일이 미완료 상태였다면 남은 할 일 개수는 1 감소한다.
- 삭제된 할 일이 완료 상태였다면 남은 할 일 개수는 변경되지 않는다.
- 삭제 후 할 일이 하나도 없다면 빈 상태 메시지를 보여준다.

## 8. 할 일 메모 추가

### 상황

사용자가 생성된 할 일에서 메모 추가 동작을 실행한다.

### 기대 상태

- 해당 할 일 아래에 메모 편집 영역이 열린다.
- 다른 할 일의 메모 편집 영역이 열려 있었다면 닫힌다.
- 사용자는 textarea에 메모를 입력할 수 있다.
- 저장하면 메모가 해당 할 일 제목 아래에 표시된다.
- 취소하면 기존 목록 상태로 돌아간다.
- 남은 할 일 개수는 변경되지 않는다.

## 9. 할 일 메모 수정

### 상황

사용자가 메모가 있는 할 일에서 메모 수정 동작을 실행한다.

### 기대 상태

- 해당 할 일 아래에 기존 메모가 들어 있는 textarea가 열린다.
- 저장하면 수정된 메모가 목록에 반영된다.
- 목록에서는 메모가 2줄까지만 표시된다.
- 취소하면 기존 메모가 유지된다.
- 완료된 할 일에서도 같은 방식으로 메모를 수정할 수 있다.

## 10. 할 일 메모 비우기

### 상황

사용자가 메모 편집 상태에서 메모 내용을 비운 뒤 저장한다.

### 기대 상태

- 해당 할 일의 메모가 삭제된다.
- 목록에서 메모 내용 영역이 사라진다.
- 할 일 제목, 완료 상태, 남은 할 일 개수는 변경되지 않는다.

## 11. 회원가입

### 상황

사용자가 계정을 새로 만든다.

### 기대 상태

- 사용자는 로그인 ID, 닉네임, 이메일, 비밀번호, 비밀번호 확인을 입력한다.
- 중복된 로그인 ID나 이메일은 사용할 수 없다.
- 비밀번호와 비밀번호 확인이 다르면 에러 메시지를 보여준다.
- 회원가입에 성공하면 로그인 화면 또는 Todo 앱 진입 흐름으로 이동할 수 있다.

## 12. 로그인

### 상황

사용자가 로그인 ID와 비밀번호로 로그인한다.

### 기대 상태

- 사용자는 이메일이 아니라 로그인 ID로 로그인한다.
- 로그인에 성공하면 Todo 앱 화면으로 이동한다.
- 로그인에 실패하면 에러 메시지를 보여준다.
- 로그인 후에는 자신의 Todo만 볼 수 있다.

## 13. 로그아웃

### 상황

로그인한 사용자가 로그아웃한다.

### 기대 상태

- 현재 refresh token은 무효화된다.
- 사용자는 로그인 화면으로 돌아간다.
- 로그아웃 후 Todo 앱 화면에 접근하면 다시 로그인이 필요하다.

## 14. 아이디 찾기

### 상황

사용자가 로그인 ID를 잊어버렸다.

### 기대 상태

- 사용자는 가입한 이메일을 입력한다.
- 앱은 인증 코드를 실제 메일로 발송한다.
- 사용자는 인증 코드를 입력한다.
- 인증 코드가 유효하면 로그인 ID를 확인한다.
- 인증 코드가 틀렸거나 만료되면 에러 메시지를 보여준다.

## 15. 비밀번호 재설정

### 상황

사용자가 비밀번호를 잊어버렸다.

### 기대 상태

- 사용자는 가입한 이메일을 입력한다.
- 앱은 인증 코드를 실제 메일로 발송한다.
- 사용자는 인증 코드를 입력한다.
- 인증 코드가 유효하면 새 비밀번호를 입력할 수 있다.
- 새 비밀번호 저장 후 사용자는 새 비밀번호로 로그인할 수 있다.

## 16. 로그인 후 비밀번호 변경

### 상황

로그인한 사용자가 비밀번호를 변경한다.

### 기대 상태

- 사용자는 현재 비밀번호와 새 비밀번호를 입력한다.
- 현재 비밀번호가 맞으면 새 비밀번호로 변경된다.
- 비밀번호 변경 후 기존 refresh token은 무효화된다.
- 사용자는 새 비밀번호로 다시 로그인할 수 있다.

## 17. 회원탈퇴

### 상황

로그인한 사용자가 계정을 삭제한다.

### 기대 상태

- 사용자는 비밀번호를 재입력한다.
- 비밀번호가 맞으면 계정이 hard delete로 삭제된다.
- 사용자의 Todo와 인증 관련 기록도 함께 삭제된다.
- 회원탈퇴 후 로그인 화면으로 이동한다.
- 같은 로그인 ID와 이메일로 다시 가입할 수 있다.

- 메모가 있는 할 일 상태
- 메모 편집 상태
- 회원가입 상태
- 로그인 상태

- 아이디 찾기 인증 코드 입력 상태
- 아이디 찾기 결과 상태
- 비밀번호 재설정 상태
- 로그인 후 비밀번호 변경 상태
