# 요구사항 정의서

## 목적

이 문서는 Todo App MVP와 승인된 확장 기능의 기능 요구사항과 인수 조건을 정의한다.

## 기능 범위

- 할 일 추가
- 할 일 완료 처리와 완료 취소
- 할 일 삭제
- 남은 할 일 개수 표시
- 빈 상태 표시
- 할 일 메모 추가, 수정, 비우기
- 회원가입
- 로그인, 토큰 갱신, 로그아웃
- 이메일 인증 기반 아이디 찾기
- 이메일 인증 기반 비밀번호 재설정
- 로그인 후 비밀번호 변경
- 회원탈퇴
- 로그인 사용자별 Todo 데이터 분리

## 1. 할 일 추가

### 요구사항

사용자는 입력창에 할 일을 작성하고 목록에 추가할 수 있다.

### 인수 조건

- 사용자는 텍스트를 입력해 할 일을 추가할 수 있다.
- 앞뒤 공백은 제거된다.
- 여러 개의 연속된 공백은 하나의 공백으로 정리된다.
- 빈 문자열만 입력한 경우 할 일은 추가되지 않는다.
- 빈 문자열만 입력한 경우 사용자에게 에러 메시지를 보여준다.
- 사용자가 다시 유효한 값을 입력하면 에러 메시지는 해소된다.
- 새로 추가된 할 일은 미완료 상태다.
- 할 일이 추가되면 입력창은 비워진다.
- 새로 추가된 할 일은 목록에서 확인할 수 있다.

## 2. 할 일 완료 처리와 완료 취소

### 요구사항

사용자는 할 일을 체크해 완료 상태로 바꿀 수 있고, 다시 체크를 해제해 미완료 상태로 되돌릴 수 있다.

### 인수 조건

- 미완료 할 일을 체크하면 완료 상태가 된다.
- 완료 할 일을 다시 체크 해제하면 미완료 상태가 된다.
- 완료된 할 일은 목록에서 사라지지 않는다.
- 완료된 할 일은 미완료 할 일과 시각적으로 구분된다.
- 완료 상태 변경은 남은 할 일 개수에 반영된다.

## 3. 할 일 삭제

### 요구사항

사용자는 더 이상 필요하지 않은 할 일을 삭제할 수 있다.

### 인수 조건

- 사용자는 각 할 일 항목에서 삭제 동작을 실행할 수 있다.
- 삭제 동작을 실행하면 해당 할 일은 목록에서 바로 사라진다.
- 삭제된 할 일은 남은 할 일 개수에 반영된다.

## 4. 남은 할 일 개수 표시

### 요구사항

사용자는 아직 완료하지 않은 할 일의 개수를 확인할 수 있다.

### 인수 조건

- 앱은 미완료 할 일 개수를 표시한다.
- 완료된 할 일은 남은 개수에 포함하지 않는다.
- 할 일 추가, 완료 상태 변경, 삭제 후 개수가 갱신된다.
- 할 일이 없으면 남은 개수는 0으로 표시된다.

## 5. 빈 상태 표시

### 요구사항

목록에 할 일이 없을 때 사용자는 현재 할 일이 없다는 상태를 알 수 있다.

### 인수 조건

- 할 일이 하나도 없으면 빈 상태 메시지를 보여준다.
- 할 일이 추가되면 빈 상태 메시지는 사라진다.
- 빈 상태에서도 할 일 입력은 가능하다.

## 6. 할 일 메모

### 요구사항

사용자는 생성된 할 일에 선택 메모를 추가하고, 수정하고, 비울 수 있다.

### 인수 조건

- 할 일 추가 시점에는 메모를 입력하지 않는다.
- 사용자는 생성된 할 일 항목에서 메모 추가 동작을 실행할 수 있다.
- 메모 편집은 한 번에 하나의 할 일에서만 열린다.
- 메모는 선택 입력이다.
- 메모 최대 길이는 500자다.
- 메모가 저장되면 해당 할 일 제목 아래에 표시된다.
- 목록에서 메모는 2줄까지만 표시된다.
- 메모 편집 textarea에서는 전체 메모를 볼 수 있다.
- 기존 메모를 수정하면 목록에 수정된 메모가 반영된다.
- 빈 값으로 저장하면 메모가 삭제된다.
- 메모가 없는 할 일에는 메모 내용 영역을 표시하지 않는다.
- 완료된 할 일도 메모를 볼 수 있고 수정할 수 있다.
- 메모 추가, 수정, 비우기는 남은 할 일 개수에 영향을 주지 않는다.
- Todo 삭제 시 해당 Todo의 메모도 함께 사라진다.

## 7. 회원가입

### 요구사항

사용자는 로그인 ID, 닉네임, 이메일, 비밀번호를 입력해 계정을 만들 수 있다.

### 인수 조건

- 로그인 ID는 필수 입력이다.
- 로그인 ID는 전체 사용자 중 중복될 수 없다.
- 닉네임은 필수 입력이다.
- 이메일은 필수 입력이다.
- 이메일은 전체 사용자 중 중복될 수 없다.
- 비밀번호는 필수 입력이다.
- 비밀번호 확인 값은 비밀번호와 일치해야 한다.
- 비밀번호는 평문으로 저장하지 않는다.
- 회원가입에 성공하면 사용자는 로그인할 수 있다.
- 회원가입 실패 시 사용자는 실패 이유를 알 수 있다.

## 8. 로그인, 토큰 갱신, 로그아웃

### 요구사항

사용자는 로그인 ID와 비밀번호로 로그인하고, JWT 기반 인증 상태를 유지하며, 로그아웃할 수 있다.

### 인수 조건

- 로그인은 이메일이 아니라 로그인 ID를 사용한다.
- 로그인 ID와 비밀번호가 일치하면 access token과 refresh token을 발급한다.
- access token은 API 인증에 사용된다.
- refresh token은 HTTP-only cookie로 전달된다.
- refresh token 원문은 저장하지 않는다.
- refresh token으로 access token을 재발급할 수 있다.
- 유효하지 않은 refresh token으로는 access token을 재발급할 수 없다.
- 로그아웃하면 현재 refresh token은 무효화된다.
- 로그아웃 후 같은 refresh token으로 access token을 재발급할 수 없다.
- 로그인하지 않은 사용자는 인증이 필요한 Todo API를 사용할 수 없다.

## 9. 로그인 사용자별 Todo 데이터 분리

### 요구사항

Todo 데이터는 로그인한 사용자별로 분리되어야 한다.

### 인수 조건

- Todo 생성 시 현재 로그인한 사용자가 소유자로 기록된다.
- Todo 목록 조회는 현재 로그인한 사용자의 Todo만 반환한다.
- Todo 완료 변경, 메모 수정, 삭제는 현재 로그인한 사용자의 Todo에만 적용된다.
- 다른 사용자의 Todo id를 알고 있어도 조회, 수정, 삭제할 수 없다.
- 남은 할 일 개수는 현재 로그인한 사용자의 Todo만 기준으로 계산된다.

## 10. 이메일 인증

### 요구사항

사용자는 아이디 찾기와 비밀번호 재설정을 위해 이메일 인증 코드를 받을 수 있다.

### 인수 조건

- 사용자는 이메일 주소로 인증 코드를 요청할 수 있다.
- 인증 코드는 실제 메일로 발송된다.
- 메일 발송은 Nodemailer를 사용한다.
- 인증 코드는 제한된 시간 동안만 유효하다.
- 만료된 인증 코드는 사용할 수 없다.
- 잘못된 인증 코드는 거부된다.
- 이미 사용한 인증 코드는 다시 사용할 수 없다.

## 11. 아이디 찾기

### 요구사항

사용자는 가입한 이메일을 인증한 뒤 로그인 ID를 확인할 수 있다.

### 인수 조건

- 사용자는 이메일 인증을 완료해야 로그인 ID를 확인할 수 있다.
- 인증되지 않은 이메일로는 로그인 ID를 보여주지 않는다.
- 해당 이메일로 가입한 계정이 없으면 계정을 찾을 수 없음을 알린다.
- 인증에 성공하면 해당 이메일의 로그인 ID를 보여준다.

## 12. 이메일 인증 기반 비밀번호 재설정

### 요구사항

비밀번호를 잊은 사용자는 이메일 인증 후 새 비밀번호를 설정할 수 있다.

### 인수 조건

- 사용자는 로그인하지 않은 상태에서 비밀번호 재설정을 시작할 수 있다.
- 사용자는 가입한 이메일 인증을 완료해야 새 비밀번호를 설정할 수 있다.
- 새 비밀번호와 비밀번호 확인 값은 일치해야 한다.
- 새 비밀번호는 평문으로 저장하지 않는다.
- 비밀번호 재설정 후 기존 refresh token은 무효화된다.
- 비밀번호 재설정 후 새 비밀번호로 로그인할 수 있다.

## 13. 로그인 후 비밀번호 변경

### 요구사항

로그인한 사용자는 현재 비밀번호를 확인한 뒤 새 비밀번호로 변경할 수 있다.

### 인수 조건

- 사용자는 로그인 상태에서만 비밀번호를 변경할 수 있다.
- 현재 비밀번호가 일치해야 비밀번호를 변경할 수 있다.
- 새 비밀번호와 비밀번호 확인 값은 일치해야 한다.
- 새 비밀번호는 평문으로 저장하지 않는다.
- 비밀번호 변경 후 기존 refresh token은 무효화된다.
- 사용자는 새 비밀번호로 다시 로그인할 수 있다.

## 14. 회원탈퇴

### 요구사항

로그인한 사용자는 비밀번호를 재확인한 뒤 회원탈퇴할 수 있다.

### 인수 조건

- 사용자는 로그인 상태에서만 회원탈퇴할 수 있다.
- 비밀번호가 일치해야 회원탈퇴할 수 있다.
- MVP에서는 회원탈퇴를 hard delete로 처리한다.
- 회원탈퇴 시 사용자 계정은 삭제된다.
- 회원탈퇴 시 해당 사용자의 Todo, refresh token, 이메일 인증 기록은 함께 삭제된다.
- 회원탈퇴 후 해당 계정으로 로그인할 수 없다.
- 회원탈퇴 후 같은 로그인 ID와 이메일로 다시 가입할 수 있다.
