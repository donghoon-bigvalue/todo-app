# 디자인 브리프

## 목적

이 문서는 Todo App MVP의 UI 방향, 화면 상태, 컴포넌트, 최소 디자인 시스템을 정의한다.

Figma 작업에서는 이 문서를 기준으로 디자인 시스템과 화면을 만든다.

## 디자인 방향

Todo App은 단순한 체크리스트형 앱이다.

디자인은 장식보다 명확성과 빠른 입력을 우선한다. 사용자는 앱을 열자마자 할 일을 입력하고, 남은 일을 확인하고, 완료 여부를 체크할 수 있어야 한다.

## UI 원칙

- 한 화면에서 핵심 작업을 모두 수행할 수 있어야 한다.
- 할 일 입력 영역은 첫 화면에서 바로 보여야 한다.
- 완료된 할 일은 목록에 남기되, 남은 할 일보다 낮은 강조도로 표현한다.
- 삭제는 별도 확인 단계 없이 바로 실행한다.
- 메모는 생성된 할 일에서 필요한 경우에만 추가한다.
- 메모 편집은 한 번에 하나의 할 일만 열린다.
- 목록의 메모는 제목 아래에 2줄까지만 표시한다.
- 빈 상태와 에러 상태를 명확히 구분한다.
- 불필요한 장식이나 복잡한 설정은 MVP에서 제외한다.

## 화면 구성

MVP 화면은 하나의 메인 화면으로 구성한다.

필요한 UI 영역:

- 앱 제목: `할 일 체크리스트`
- 남은 할 일 개수
- 할 일 입력창
- 추가 버튼
- 할 일 목록
- 빈 상태 메시지
- 입력 에러 메시지
- 할 일별 메모 표시 영역
- 할 일별 메모 편집 영역

## Figma에서 필요한 화면 상태

Figma에서는 최소한 다음 화면 상태를 만든다.

### 1. 빈 상태

할 일이 하나도 없는 상태.

포함 요소:

- 앱 제목
- 남은 할 일 개수 0
- 할 일 입력창
- 추가 버튼
- 빈 상태 메시지

### 2. 기본 목록 상태

미완료 할 일이 하나 이상 있는 상태.

포함 요소:

- 앱 제목
- 남은 할 일 개수
- 할 일 입력창
- 추가 버튼
- 미완료 할 일 항목

### 3. 완료 항목 포함 상태

미완료 할 일과 완료된 할 일이 함께 있는 상태.

포함 요소:

- 미완료 할 일 항목
- 완료된 할 일 항목
- 완료된 항목의 낮은 강조도 표현
- 완료된 항목의 취소선
- 남은 할 일 개수

### 4. 입력 에러 상태

사용자가 빈 값이나 공백만 입력한 상태로 추가를 시도한 상태.

포함 요소:

- 할 일 입력창
- 에러 메시지
- 추가되지 않은 목록 상태

### 5. 메모가 있는 항목 상태

할 일에 메모가 저장된 상태.

포함 요소:

- 할 일 제목
- 메모 추가 또는 수정 버튼
- 제목 아래 2줄까지 표시되는 메모 내용
- 기존 완료, 삭제 동작

### 6. 메모 편집 상태

사용자가 특정 할 일의 메모를 추가하거나 수정하는 상태.

포함 요소:

- 편집 대상 할 일 제목
- 메모 textarea
- 저장 버튼
- 취소 버튼
- 기존 완료, 삭제 동작

## 최소 디자인 시스템

MVP에서는 거창한 디자인 시스템이 아니라 작은 UI 키트 수준으로 시작한다.

### 색상 토큰

- `background`: 앱 배경
- `surface`: 입력 영역과 할 일 항목 배경
- `text-primary`: 주요 텍스트
- `text-secondary`: 보조 텍스트
- `border`: 경계선
- `accent`: 주요 동작과 체크 상태
- `danger`: 삭제와 에러

### 간격 토큰

- `space-4`
- `space-8`
- `space-12`
- `space-16`
- `space-24`
- `space-32`

### 타이포그래피 토큰

- 기본 폰트: `Pretendard`
- 대체 폰트: system sans-serif
- 구현 시 `Pretendard`를 웹폰트로 포함한다.
- `title`: 앱 제목
- `body`: 할 일 텍스트
- `supporting`: 남은 개수, 빈 상태, 에러 메시지

### 형태 토큰

- `radius-small`: 입력창, 버튼, 할 일 항목

## 컴포넌트

Figma에서는 다음 컴포넌트를 만든다.

### Button

용도:

- 할 일 추가
- 할 일 삭제
- 메모 추가 또는 수정
- 메모 저장
- 메모 편집 취소

필요 상태:

- 기본
- 강조
- 위험
- 비활성

### Text Input

용도:

- 할 일 입력

필요 상태:

- 기본
- 포커스
- 에러

### Checkbox

용도:

- 할 일 완료 처리와 완료 취소

필요 상태:

- 미체크
- 체크

### Todo Item

용도:

- 할 일 하나를 표시

필요 상태:

- 미완료
- 완료
- 메모 있음
- 메모 편집 중

### Empty State

용도:

- 할 일이 하나도 없을 때 표시

### Error Message

용도:

- 빈 입력 제출 시 표시

## 인터랙션 기준

- 사용자는 입력창에 텍스트를 입력하고 추가 버튼으로 할 일을 추가한다.
- Enter 키로도 할 일을 추가할 수 있다.
- 빈 값이나 공백만 입력하면 에러 메시지를 보여준다.
- 사용자는 체크박스로 완료 상태를 바꿀 수 있다.
- 완료된 할 일에는 취소선을 적용한다.
- 사용자는 삭제 버튼을 눌러 할 일을 바로 삭제할 수 있다.
- 사용자는 생성된 할 일에서 메모 버튼을 눌러 메모 편집 영역을 연다.
- 메모 버튼은 메모가 없으면 메모 추가, 메모가 있으면 메모 수정 동작으로 이해할 수 있어야 한다.
- 메모 편집 영역은 한 번에 하나만 열린다.
- 사용자는 메모를 저장하거나 취소할 수 있다.
- 빈 메모를 저장하면 해당 할 일의 메모를 삭제한다.

## 접근성 기준

- 입력창에는 명확한 label이 있어야 한다.
- 추가 버튼은 동작을 이해할 수 있는 이름을 가져야 한다.
- 체크박스는 어떤 할 일을 완료 처리하는지 알 수 있어야 한다.
- 삭제 버튼은 어떤 할 일을 삭제하려는지 알 수 있어야 한다.
- 메모 버튼은 어떤 할 일의 메모를 추가하거나 수정하는지 알 수 있어야 한다.
- 메모 textarea에는 명확한 label이 있어야 한다.
- 메모 저장 버튼과 취소 버튼은 키보드로 조작할 수 있어야 한다.
- 에러 메시지는 입력창과 연결되어야 한다.
- 키보드만으로 추가, 완료 처리, 삭제, 메모 편집이 가능해야 한다.
